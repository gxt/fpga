# T008: 远程综合服务器工作流搭建

## 执行环境
**执行环境**：远端（综合服务器 `gxt@192.168.200.202`）＋ 本地

## 接口规范
- 输入：远程服务器已确认（`gxt@192.168.200.202`，Vivado v2025.1 与本地一致，登记于 `.tao/knowledge/registry.md`；文件交换方式待 T008 阶段确认，scp 候选）；coralnpu 源码；bazel 生成的 RTL 产物（`//hdl/chisel/src/coralnpu:core_mini_axi_cc_library` 等）
- 输出：主仓库 `synth/` 下的工作流脚本（同步 coralnpu、RTL 产物、工程目录）；**服务器执行拓扑记录（`.tao/knowledge/synth-server.md`）**
- 约束：本机不承担综合主责；服务器访问信息登记到 `.tao/knowledge/registry.md` 机器路由表；不把密码/密钥写入任务文件或脚本

## 验收标准
1. 服务器信息（地址、Vivado 版本、文件交换方式）已确认并登记到 registry.md
2. 同步脚本可将 coralnpu 源码与 bazel 生成的 RTL（如 `//hdl/chisel/src/coralnpu:core_mini_axi_cc_library`）推送到服务器并可拉回结果
3. 远程执行 `vivado -version`（或等效）输出已记录，确认版本 ≥ 项目要求且支持目标器件
4. **确定服务器执行拓扑并写入 `.tao/knowledge/synth-server.md`，至少覆盖三要素**：
   - ① 服务器跑什么：`bazel fusesoc_build`（服务器上完整 bazel 流程）还是同步工程后纯 Vivado（本地生成/推送工程，服务器只跑 synthesis/implementation）
   - ② 依赖到位方式：本地 bazel 产物推送 / 服务器自拉缓存（含 RISC-V 工具链、IP 等第三方依赖的放置与版本确认）
   - ③ 每步执行机器：明确综合、实现、生成 bitstream 每一步在本地还是服务器执行
5. **license 检查**：确认服务器 Vivado 能识别目标器件（`xc7v2000tflg1925-1`，及可选的 xcvu13p 基线器件），记录 license 检查方式与结果（全功能 license 已确认，此处仅验证识别能力）
