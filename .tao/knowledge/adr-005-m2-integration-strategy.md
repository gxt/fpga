# ADR-005: M2 阶段集成策略

## 背景

M2 目标：在 DualV7 板（xc7v2000t）上跑起完整 SoC（CoralNPUChiselSubsystem）。需要决定集成顺序、裁剪策略和验证方法。

## 决策

### 1. 集成顺序：渐进式，每阶段独立验证

**阶段**：
1. T017：RVV 核上板（消除综合/时序风险）
2. T018：TL-UL + crossbar 集成（验证总线互连）
3. T019：DDR3 集成（验证大存储通路）
4. T020：SRAM + 外设（扩展存储和基本外设）
5. T021：完整 SoC 收尾（补剩余外设，测试集跑通）

**理由**：
- 每阶段只增加尽量少的部件，运行测试程序确认该部分有效后再进下一阶段
- 降低调试复杂度，快速定位问题
- 符合"先核心后外围"的工程原则

### 2. 总线架构：TL-UL crossbar

**选择**：使用 TileLink-UL（TL-UL）crossbar（CoralNPUXbar）而非直接 AXI 连接。

**理由**：
- coralnpu 完整 SoC 代码已基于 TL-UL crossbar 实现，复用现有代码减少工作量
- crossbar 支持多主机多从机，便于扩展
- 与上游 coralnpu 项目保持一致

**拒绝方案**：
- 保留 CoreMiniAxi（AXI 接口）：需重写外设连接，工作量大
- 自建 AXI crossbar：重复造轮子，且与上游不一致

### 3. 裁剪策略：最小可用 SoC

**裁剪项**：
- ISP：无摄像头输入，完全移除或保留空 TLUL 端口
- DMA/spi2tlul：可选，根据资源和需求决定
- I2C master：暂不需要
- 其他外设：仅保留基本必需（uart0/1、gpio、clint、plic、sram）

**理由**：
- 先跑通最小可用 SoC，再逐步扩展
- 减少资源占用，确保时序收敛
- 降低集成风险

### 4. 存储策略：TCM + SRAM + DDR3

**存储层次**：
- ITCM/DTCM：核内 TCM（8KB + 32KB），用于代码和栈
- SRAM：512KB-1MB（0x20000000），用于 `.extdata` 段和堆
- DDR3：2GB（0x80000000），用于大容量数据

**理由**：
- TCM 提供低延迟访问，适合代码和栈
- SRAM 提供中等容量，避免频繁访问 DDR
- DDR3 提供大容量，支持 matmul/highmem 测试

### 5. 验证策略：先仿真后上板

**流程**：
1. xsim 仿真验证功能正确性
2. 综合验证时序和资源
3. 上板验证实际运行

**理由**：
- 仿真可快速发现问题，减少上板调试时间
- 综合确保时序收敛，避免上板后时序违例
- 上板验证实际硬件行为

## 影响

1. **开发时间**：渐进式集成可能增加总时间，但降低调试时间
2. **资源占用**：裁剪后资源占用可控，但需实测确认
3. **代码修改**：需修改 CrossbarConfig 和 SoCChiselConfig 以裁剪外设
4. **测试覆盖**：每个阶段有明确测试目标，确保质量

## 已拒绝方案

1. **一次性集成所有模块**：风险高，调试困难
2. **保留 AXI 接口**：需重写外设连接，工作量大
3. **不裁剪 ISP**：无摄像头输入，浪费资源
4. **直接上板调试**：仿真发现问题更快，上板调试成本高
